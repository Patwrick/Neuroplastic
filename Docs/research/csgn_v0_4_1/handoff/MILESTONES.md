# Milestones and decision gates

These are implementation work slices, not a forecast of calendar time. Every slice ends with the report template, commands, code identity, tests, failures and explicit next action. Negative results count as progress when the controls are correct.

## M0 — inspect and preserve

Inspect actual repo root, branch/worktree, dirty files, instructions, manifests, tests, available CPU/GPU, and memory. Validate the release and rerun its reference suite. Record reusable tooling versus legacy learning code without turning this into a full v0.2 implementation audit. Select an isolated namespace, local environment and evidence directories. Output `REPO_ASSESSMENT.md`, environment report and `M0_REPORT.md`.

Exit: source version, authority, package integrity, environment and non-destructive plan are clear. A genuine repo-access failure must be reported, not replaced with a guessed checkout.

## M1 — executable scientific contracts

Implement functional PyTorch endpoint intervals, receiver envelope, workspace, snapshots, projected writes and conditional exact outer gradients. Compare with the supplied independent NumPy reference. Add endpoint-correction, two-tier decay, source/target/version, no-op, rejection and numeric tests. Add target-leakage assertions before any training code.

Exit: exact small cases and randomized tests pass stated tolerances; gradient checks include full-path versus detach controls, stable active faces and explicit nondifferentiable exclusions. No real learned capability claim yet.

## M2 — smallest complete lifecycle

Implement T1 and a simple delta baseline; build prediction, delayed feedback record, online write, distractor, synchronous slow fitting, and fast-off recall. Keep shared theta and graph initially small enough for CPU. Include batch-isolation and cold-evaluation no-write tests. A tiny overfit diagnostic on a known feasible small task can establish plumbing but is labeled as such.

Exit: an actual end-to-end command executes all lifecycle phases and logs metrics, successful or not. It must not silently substitute a standalone ideal matrix memory for the graph. Complete within first-task budgets and return the first report for review. Do not automatically launch M3 sweeps.

## M3 — learned representations, useful writes, strong comparators

After review, train shared encoder/router/message parameters on short episodes with continuous outer paths. Compare simple delta memory, static graph, replay-only, fixed graph without sleep, and fixed graph with sleep. Use the same feedback and training/hyperparameter budgets. Add full-path/detached-path and old/new reserve ablations. Monitor reachability, conditioning, projected no-progress, and downstream write utility.

Pilot defaults: 3 independent training seeds, 64 evaluation episodes per task checkpoint, bounded single-device jobs. These are engineering budgets, not powered statistical confirmation. Use the pilot to check cost and variance, not to select a winner from test data.

Exit: reproducible trained behavior or a diagnosed failure supported by logs. A low snapshot loss with no query benefit is a learning-alignment problem, not evidence for H1.

## M4 — causal memory and transfer

Run same-theta/G slow transplants, matched erasure, negative controls, delay and interference sweeps, and unseen-input rule transfer. Compare state-dependent/stable-address variants with the same information. Measure cold recall on still-valid prior contexts and separately on superseded associations.

Exit: distinguish memory storage, generic damage, lookup shortcuts and genuinely reusable task structure. Failure on a held-out task family narrows the claim rather than being silently excluded.

## M5 — independent, resource-matched confirmation

Preregister primary metric, minimum effect, retained-task tolerance, comparison set, seed count, data splits and resource budgets using pilot evidence. Freeze configurations before opening confirmation data. Use at least 10 proposed independent training seeds if resources permit; determine adequacy from variance/power rather than assuming 10 is a theorem. Report paired intervals and learning curves, failures and all seeds. Match memory and latency in separate frontiers where both cannot be simultaneously equal.

Exit: evidence supports or rejects a *specified* adaptation–retention/resource advantage. Exact hypothesis choice and effect thresholds must be fixed before results. No global lifelong-learning claim.

## M6 — optional complexity, only where evidence warrants

Test structural adaptation as a separate H3 study after fixed-graph learning/consolidation works. Then assess lower precision, sparse kernels, offloading, and longer environments. Each addition receives its own overhead charge and ablation. A failed complex variant does not invalidate a useful simpler mechanism; a useful simpler baseline is a legitimate redesign destination.

## Stop and diagnose

Immediately stop the affected run for nonfinite state, feasibility failure beyond tolerance, label leakage, an invalid gradient claim, hidden state aliasing, unaccounted full-graph storage, a destructive migration, or a missing required artifact. Do not stop safe unrelated coding.

Stop scaling when reproducible baselines dominate, cold recall remains a shortcut, or projected writes routinely have no useful effect. Diagnose reachability and gradients first, then representations, target contracts, or capacity. Change one factor through a documented decision record; do not add several memory subsystems at once.
